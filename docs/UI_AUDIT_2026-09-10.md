### 7.2 云端足迹统计卡片接入「我的」页

服务端 `GET /trajectory/stats` 在 SQL 侧一次聚合、只回传一行，因此**卡片开销与轨迹条数无关** ——
这是引入它的核心理由（轨迹随使用时间累积，本地求和迟早拖慢页面）。

实机联调（Java 服务端 + 模拟器 `http://10.0.2.2:3000`，走查账号种入 3 条轨迹）：

| `28_profile_logged_out` | 未登录的「我的」页 | **整卡隐藏**（不重复堆叠登录引导，页面已有「点击头像登录」） |
| `29_profile_cloud_stats` | 已登录 | 44.2 km / 3 次 / 4 小时 / 2240 m / 90 个采样点，日期范围 2026/03/15 — 2026/09/08，右下「比本地多 3 条（含其他设备）」 |

### 7.3 走查中发现并修复的问题

| 现象 | 根因 | 处理 |
|------|------|------|
| debug 包无法访问 `http://` 后端，只报笼统的「网络错误」 | 主清单没有明文许可，而 Android 9（API 28）起 targetSdk ≥ 28 **默认禁止明文 HTTP** | 新增 **debug 专用**网络安全配置（`android/app/src/debug/`）放行明文；release 包不合并该配置，线上仍强制 HTTPS |
| 正式包填了 `http://` 地址会一直失败且不知原因 | 设置页对地址只做 `trim()`，而 `ping()` 的报错不区分「填错」与「被系统策略拦截」 | `AuthService.ping()` 在 release（`!kDebugMode`）下对 `http://` 直接给出明确文案；设置页提示同步补充说明 |
